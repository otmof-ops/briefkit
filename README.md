## About

**OFFTRACKMEDIA Studios** — ABN 84 290 819 896
*"Building Empires, Not Just Brands."*

BriefKit turns a folder of Markdown files into a branded, structured PDF in one command. It was extracted from The Codex, OFFTRACKMEDIA's knowledge infrastructure, where every documentation set carries an executive briefing generated by this tool.

Unlike general-purpose converters such as Pandoc or WeasyPrint, BriefKit is purpose-built for **structured briefings**: executive summaries, compliance reports, technical manuals, books and academic papers, with an auto-extracted bibliography, cross-references, a key-terms index, a metric dashboard, a clickable table of contents and a PDF outline out of the box.

It is for technical writers producing consistent branded deliverables, engineering and ops teams generating compliance, audit and procedure documents in bulk, and researchers turning Markdown into citation-aware PDFs.

**Status:** beta, version 1.1.0. The package is installed from this repository; a PyPI release is pending.

## What You Get

- **29 templates**, from `briefing` and `report` to `book`, `manual`, `academic`, `contract`, `invoice`, `deck`, `magazine` and `witness`. Run `briefkit templates` for the list with a one-line description each.
- **12 domain variants** (AI/ML, legal, medical, engineering, research, API, gaming, finance, species, historical, hardware, religion) that add domain-specific sections, selected by path rule, by flag, or by whole-word keyword detection.
- **20 color presets**; one line switches the entire look, and the brand's fonts reach every template.
- **Navigation that works**: a document outline (bookmarks), a clickable table of contents, and Markdown `#anchors` that jump to their heading.
- **Auto-extracted bibliography** in six citation formats (APA, author-year, bracketed, legislation, RFC, case law), cross-references, key terms and metrics.
- **Document IDs**: a persistent, locked registry with a configurable format.
- **Batch processing** that skips current output and rebuilds what is stale, including after a README or configuration change.
- **Reproducible output**: with `SOURCE_DATE_EPOCH` set, the same input produces byte-identical PDFs.
- **Safe on untrusted input**: link schemes are allowlisted, headings and brand strings are escaped before they reach the PDF engine, output paths are contained, and a failed build never destroys the previous PDF. See [SECURITY.md](SECURITY.md).
- **Fully offline**: three runtime dependencies (ReportLab, PyYAML, Pillow), no AI APIs, no telemetry, no network requests.

## Installation

### Requirements

| Dependency | Version | Notes |
|---|---|---|
| Python | 3.10 or newer | Tested on 3.10 to 3.13 (Linux, macOS, Windows) |
| ReportLab | 4.0 to 4.x | PDF engine, installed automatically |
| PyYAML | 6.0.1 to 6.x | Configuration, installed automatically |
| Pillow | 10.0 to 12.x | Logo images, installed automatically |
| pypdf | 5.0 to 6.x, optional | Read-back checks in `briefkit quality` and `briefkit selftest` (`pip install "briefkit[quality]"`) |

### From Git

```bash
pip install "git+https://github.com/otmof-ops/briefkit.git"
```

### From Source

```bash
git clone https://github.com/otmof-ops/briefkit.git
cd briefkit
pip install -e ".[dev]"
```

### Verify

```bash
briefkit --version
briefkit selftest
```

`selftest` builds a small document set in a temporary directory, reads the PDF back, and exits 1 if anything is wrong. It writes nothing into your project.

## Quick Start

```bash
# Optional: write a briefkit.yml with every setting commented
briefkit init

# One directory of numbered Markdown files -> one PDF next to the sources
briefkit generate docs/api/authentication/

# Every eligible directory under a root; unchanged ones are skipped
briefkit batch docs/

# What is current, stale or missing (add --check to exit 1 for CI)
briefkit status docs/

# Generate and open in your PDF viewer
briefkit preview docs/api/authentication/
```

For a guided first run see [docs/quick-start.md](docs/quick-start.md).

## How Sources Are Read

A **documentation set** is a directory holding numbered Markdown files. BriefKit reads:

| File | Role |
|---|---|
| `01-*.md`, `02-*.md`, ... | Chapters, in order (`content.numbered_doc_pattern`) |
| `README.md` | Title (first `#` heading) and overview |
| `00-what-is-*.md` | Orientation document (what / why / who) |
| `engineering-brilliance.md`, `guide.md`, `preface.md`, `glossary.md` | Optional companion sections, template dependent |
| `*.pdf` file names | Bibliography entries (the PDFs are not opened) |

A directory that holds numbered files is a documentation set whatever its depth; a directory whose children are documentation sets is a subject, and one whose grandchildren are is a division. The default `briefing` template renders each level differently. Details: [docs/directory-structure.md](docs/directory-structure.md).

## Commands

| Command | Purpose |
|---|---|
| `briefkit generate <path>` | Generate one PDF (`--output` may name a file or a directory) |
| `briefkit batch <root>` | Generate every eligible directory under a root |
| `briefkit init [path]` | Write a `briefkit.yml` with defaults |
| `briefkit preview <path>` | Generate and open in the system viewer |
| `briefkit status [path]` | Report current / stale / missing (`--check` exits 1 if any) |
| `briefkit assign-ids <path>` | Register document IDs for directories whose PDF exists |
| `briefkit quality <path>` | Check an existing PDF (`--strict`, `--level`) |
| `briefkit selftest` | Build and verify a fixture in a temporary directory |
| `briefkit config` | Print the resolved configuration |
| `briefkit templates` | List templates with descriptions |
| `briefkit presets` | List color presets with hex values |
| `briefkit licenses` | List license presets for generated documents |

Flags go after the subcommand. Every flag, exit code and message is in [docs/cli-reference.md](docs/cli-reference.md).

## Configuration

BriefKit works with no configuration. To customize, run `briefkit init` or write a `briefkit.yml`:

```yaml
project:
  name: "My Project"
  org: "My Company"          # cover, running head, back cover, PDF author
  tagline: "Building better docs"

brand:
  preset: "ocean"            # one of 20; see `briefkit presets`
  logo: "logo.png"           # PNG, JPEG or GIF, relative to this file

template:
  preset: "report"           # one of 29; see `briefkit templates`

layout:
  page_size: "Letter"        # A4 (default), A3, Letter, Legal, Tabloid
  orientation: "portrait"

license:
  preset: "CC-BY-4.0"        # printed on the back cover; see `briefkit licenses`
```

The file is found by walking upward from the directory you run the command in (`briefkit.yml`, `briefkit.yaml` or a `.briefkit/` directory mark the project root); pass `--config FILE` to use another. Command-line flags override the file, which overrides the defaults. Unknown keys produce a warning with the closest valid name. Every key: [docs/configuration.md](docs/configuration.md).

## Templates, Presets and Variants

- **Templates** decide the structure: cover, front matter, how chapters are laid out, what back matter appears. Each template has a design page size and margins that apply unless you set `layout.*`. [docs/templates-guide.md](docs/templates-guide.md)
- **Presets** decide the colors and fonts. `royal`, `ink` and `gothic` are set in Times, `mono` in Courier, the rest in Helvetica. [docs/presets-guide.md](docs/presets-guide.md)
- **Variants** add domain sections (a legislation index, a hyperparameter table, a key-metrics dashboard) to the `briefing`, `report`, `manual` and `academic` templates. Pick one with `--variant`, with a `variants.rules` path pattern, or let keyword detection choose; `--variant none` suppresses them. [docs/variants.md](docs/variants.md)

## Extending BriefKit

A template is a Python class: subclass `BaseBriefingTemplate`, implement `build_story`, declare traits such as the design page size, and register it with `briefkit.templates.register_template`. A variant subclasses `DocSetVariant` and is registered with `briefkit.variants.register_variant`. Registration is a code step (there is no plugin directory yet): import the module that registers your class before running the CLI. Worked examples that run: [docs/custom-templates.md](docs/custom-templates.md), [docs/custom-variants.md](docs/custom-variants.md).

## CI Integration

Install from Git, run `briefkit batch docs/`, upload `**/executive-briefing.pdf`. Set `SOURCE_DATE_EPOCH` for reproducible artifacts and use `briefkit status docs/ --check` to fail a pipeline on stale output. Ready-made GitHub Actions and GitLab snippets: [docs/ci-integration.md](docs/ci-integration.md).
